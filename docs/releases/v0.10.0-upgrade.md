# Upgrading to @incubrain/foundry 0.10.0

0.10.0 is a 0.x minor with breaking changes (pre-1.0 convention). Epic `product-validator-4n6`
(telemetry + debug pipeline) and `product-validator-xdo` (Dependabot triage). PRs #159, #160.

## Breaking

- **`hero` is opt-in on content pages.** `basePageSchema.hero` now defaults to `false` (was
  `true`). A page without a `hero:` key no longer gets an automatic `UPageHero` built from its
  SEO title — the duplicate `<h1>` that stacked above pages that build their own heading. Add
  `hero: true` to every page that relied on the implicit hero, or it loses its `<h1>`.
  (astronera: `content/pages/research.md` and `team.md` — done in incubrain/astronera#16.)
- **Row ids are server UUIDs.** `row.id` is always minted by the server; a client-sent `id` is
  kept as `data.clientId`. Anything that read `id` as an event key (`section_view_<id>`,
  `hero_view`) must read `data.clientId`. The old client keys made Polaris's id dedupe silently
  drop every repeated event.
- **`server_error` means 5xx only.** A thrown status below 500 never produces a `server_error`
  row (Polaris's own 401 uptime probe used to add ~288 a day per site). 404s stay
  `http.not_found`; refused capture POSTs become `ingest_rejected`. Error-volume dashboards and
  alerts get quieter. `data.message` is capped at 300 characters (was 500).
- **`events.debug` is dev-only.** Production sites stop echoing every event to the browser
  console. Don't set `debug: true` in a base config.

## New

- **Buffer lineage.** `GET /api/_signals/export` returns `epoch` and `meta` (`driver`, `rows`,
  `headSeq`, `oldestSeq`, `oldestTs`, `capacity`, `retentionDays`, `evictedSinceBoot`);
  `GET /api/_health` returns `buildId` and `signals: { driver, epoch }`. Additive — `rows`,
  `cursor`, `site` unchanged. Consumers reset their cursor when `epoch` changes and key rows on
  `(epoch, seq)` (Polaris does, since `polaris-pcogl`).
- **Boot report.** One `[foundry]` console line at startup, production warnings for an unset
  `NUXT_PUBLIC_SITE_ID`, the in-memory store and an unset export token, and a `site_booted` row
  (`severity: 'info'`) marking each restart in the stream.
- **Request correlation.** `x-request-id` in/out, stamped as `data.requestId` on server rows.
- **Capture health rows.** `ingest_rejected` (refused POSTs, zod `path:code` only, rate-limited),
  `client_dropped` (browser rows lost: `rejected` / `retry_exhausted` / `overflow`), `chunk_error`
  and `app_error`. The browser queue retries a failed flush once and caps at 200 rows.
- **Debug pipeline.** `pnpm smoke <url>` (HTTP contract, `--write` round trip on localhost) and
  `pnpm smoke:browser <url>` (real Chrome, desktop + mobile, hydration, console, telemetry,
  screenshots) work against any Foundry site. See `docs/debugging.md`.

## Fixed

Malformed ingest/webhook bodies return 400 (were 500); a failed buffer write no longer burns a
`seq`; `docus.css` 404 on every `nuxt dev` page (consumers too); `NUXT_E3006` on Vue-only pages;
dead `CommentToggle` in the header; 74 of 82 Dependabot alerts (#160 — the remaining 8 are beads
under `product-validator-xdo`). Full list: the 0.10.0 section of `CHANGELOG.md`.

## Release candidate check (before publishing)

`pnpm layer:publish:local` (verdaccio on `127.0.0.1:4873`), then in a worktree of each site:
`.npmrc` → `@incubrain:registry=http://127.0.0.1:4873/`, `pnpm add @incubrain/foundry@<exact
local version>`, build, and run `pnpm smoke` + `pnpm smoke:browser` against the served build.

## Deploy checklist (per site)

1. astronera: merge incubrain/astronera#16 **before or with** the bump (hero flags, layout hero
   removed, `/pilots` h1) — without it `/research` and `/team` lose their `<h1>`.
2. Bump the site to `@incubrain/foundry@^0.10.0`, build, deploy.
3. Railway: set `NUXT_PUBLIC_SITE_ID` (all three live sites currently answer `siteId: null`, so
   the Polaris identity probe is inert) and a `NUXT_SIGNAL_EXPORT_TOKEN` of **≥ 32 characters**
   (Polaris refuses shorter tokens). Don't pass the token as a Docker build arg.
4. Railway: attach a Volume and set `NUXT_SIGNAL_STORE_DIR` (0.9.0 checklist step 2) — until then
   the boot report warns that the store is in-memory.
5. Verify read-only: `pnpm smoke https://<site>` and `pnpm smoke:browser https://<site>`;
   `/api/_health` shows `0.10.0`, a `buildId` and `signals.driver: "fs"`; Polaris shows the epoch.

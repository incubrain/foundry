# Upgrading to @incubrain/foundry 0.9.0

0.9.0 is a 0.x minor with breaking changes (pre-1.0 convention). Epic `product-validator-ev2`.

## Breaking

- **`useUserIdentity` is removed** (and its auto-import), along with `userId` on event payloads
  and `visitor.anonId` on Site Events. Visitors are now counted by `visitor.hash` — a
  server-side, daily-salted sha256 of site + IP + user agent. Nothing is written to cookies or
  `localStorage`; the old `foundry_userId` localStorage key is cleared on boot. Consequence: a
  visitor returning on a later UTC day counts as a new visitor.
- **404s are no longer `server_error` rows.** Page 404s emit `http.not_found` (page + referrer);
  scanner/asset noise is skipped.

## New

- **Durable Site Event store.** Set `NUXT_SIGNAL_STORE_DIR` to an absolute directory (a Railway
  Volume mount, e.g. `/data/signals`) and the `signals` buffer persists across restarts and
  redeploys. Unset → in-memory, as before. Retention is 14 days (capacity 170k rows); a
  `quota_low` warning row is emitted at ≥90% capacity.
- **`visitor.device` / `visitor.browser` / `visitor.os`** stamped server-side (family names only).
- **`ui.outbound`** Site Events for outbound links and file downloads: `{ host, kind, ext? }`.

## Deploy checklist (per site)

1. Bump the site to `@incubrain/foundry@^0.9.0`, build, deploy.
2. Railway: attach a Volume to the service; set `NUXT_SIGNAL_STORE_DIR` to its mount path; set
   `RAILWAY_RUN_UID=0` if the image runs as non-root. (Railway: a service with a volume has brief
   downtime on each redeploy and cannot use replicas.)
3. Railway: make sure `NUXT_PUBLIC_SITE_ID` is set — `/api/_health` now ships and reports it.
4. Polaris: pin that id on the site's registry row (`siteId`), so the identity Probe asserts it
   and treats a 404 on `/api/_health` (a parked or expired domain) as down.
